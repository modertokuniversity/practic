# TimeTracker — frontend

Клієнтська частина вебзастосунку для обліку робочого часу працівників (лабораторні роботи № 6–7). Next.js 14 + TypeScript + Tailwind CSS, backend поки відсутній — усі дані мокові й живуть у браузері (Zustand + localStorage), тому інтерфейс повністю інтерактивний: таймер справді тікає, форми справді зберігають дані, заявки справді змінюють статус.

## Швидкий старт через Docker

```bash
cd lab6_frontend
docker compose up -d --build
```

Окремо frontend доступний на **http://localhost:3100**, однак для повного запуску frontend + FastAPI + PostgreSQL використовуйте загальний compose-файл із `lab5/docker-compose.yml` (див. кореневий README).

Зупинити:

```bash
docker compose down
```

## Запуск без Docker (для розробки)

```bash
npm install
npm run dev
```

Відкриється на `http://localhost:3000` (Next.js сам підбере вільний порт, якщо 3000 зайнятий).

## Демо-вхід

На `/login` доступні 5 готових акаунтів (кнопка підставляє email і демонстраційний пароль, який перевіряє FastAPI). Після входу backend повертає JWT і дані завантажуються з PostgreSQL. Перемикання ролі доступне лише до входу, у локальному демонстраційному режимі.

## Ролі й права доступу (коротко)

Повна матриця — у [`API_CONTRACT.md`](./API_CONTRACT.md#матриця-прав-доступу). Ключові правила:

- **Ручний/заднім числом запис часу** (не через живий таймер) може створити лише керівник, адміністратор, або лід конкретного проєкту — рядовий працівник лише запускає/зупиняє власний таймер.
- **Проєкти й учасники**: створювати проєкти, обирати виконавців і призначати ставку год. може лише керівник/адмін.
- **Пріоритет задач** змінює лише керівник/адмін; статус задачі — сам виконавець або керівник/адмін.
- **Оплата праці / фінансові показники** видно лише бухгалтеру, керівнику й адміністратору.

## Що реалізовано

- **Дашборд** — персональний або по підрозділу (залежно від ролі), графік годин за 7 днів, хто зараз на роботі, заявки на розгляд
- **Таймер** — старт/пауза/продовжити/обід/стоп у реальному часі (окремий облік робочого часу, пауз і обіду), прив'язка до проєкту/задачі, ручне додавання запису (лише для відповідальних ролей)
- **Табель** — таблиця з фільтрами (дата, працівник, статус), редагування й видалення обмежено правами доступу
- **Проєкти** — 12 демонстраційних проєктів, створення нового проєкту (керівник/адмін) з вибором учасників, ліда й бюджету годин
- **Сторінка проєкту** — Kanban (To do / In progress / Done) з редагованим пріоритетом задач, учасники, і повний блок **аналітики**: динаміка витраченого часу, навантаження учасників, виконання задач, планові/фактичні години, собівартість
- **Графік змін** — календар на тиждень, для керівника — по всій команді
- **Відпустки/лікарняні** — подання заявки, баланс днів, затвердження/відхилення (керівник)
- **Команда** — довідник співробітників з фільтрами і, для керівника/адміна, редагованою ставкою за годину
- **Звіти й аналітика** — графіки годин по підрозділах, динаміка запізнень, розподіл заявок, генерація та історія звітів
- **Оплата праці** (бухгалтер) — фільтри (період/підрозділ/проєкт), перегляд перед формуванням, підсумки, груповання за працівниками/проєктами, готовий вигляд сформованого звіту, історія звітів
- **Сповіщення** — дзвіночок у шапці + окрема сторінка
- **Налаштування** — профіль, перемикачі сповіщень

Повна структура проєкту та технічні деталі — у файлі [`EXPLANATION.md`](./EXPLANATION.md). Специфікація для майбутнього backend (поля сутностей, ендпоїнти, права доступу) — у [`API_CONTRACT.md`](./API_CONTRACT.md).
